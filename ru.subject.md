## Глава IV — Обязательная часть

| | |
|---|---|
| **Имя функции** | `get_next_line` |
| **Прототип** | `char *get_next_line(int fd);` |
| **Файлы для сдачи** | `get_next_line.c`, `get_next_line_utils.c`, `get_next_line.h` — все в корне репозитория |
| **Параметры** | `fd`: файловый дескриптор, из которого нужно читать |
| **Возвращаемое значение** | Прочитанная строка: корректное поведение<br>`NULL`: больше нечего читать или произошла ошибка |
| **Внешние функции** | `read`, `malloc`, `free` |
| **Описание** | Напишите функцию, которая возвращает строку, прочитанную из файлового дескриптора |

- Повторные вызовы вашей функции `get_next_line()` (например, в цикле) должны позволять читать текстовый файл, на который указывает файловый дескриптор, **по одной строке за раз**.
- Ваша функция должна возвращать прочитанную строку.
  Если читать больше нечего или произошла ошибка, она должна вернуть `NULL`.
- Убедитесь, что ваша функция работает правильно как при чтении из файла, так и при чтении со стандартного ввода.
- **Обратите внимание**: возвращаемая строка должна включать завершающий символ `\n`, кроме случая, когда достигнут конец файла и файл не заканчивается символом `\n`.
- Ваш заголовочный файл `get_next_line.h` должен содержать как минимум прототип функции `get_next_line()`.
- Все нужные вам вспомогательные функции поместите в файл `get_next_line_utils.c`.

> ℹ️ Хорошим началом будет разобраться, что такое `статическая переменная` (static variable).

- Поскольку в `get_next_line()` вам придётся читать файлы, добавьте к вызову компилятора следующую опцию: `-D BUFFER_SIZE=n`
  Она задаёт размер буфера для `read()`.
  Значение размера буфера будет изменяться вашими проверяющими и Moulinette при тестировании вашего кода.

> ⚠️ Проект должен компилироваться как с флагом `-D BUFFER_SIZE`, так и без него (в дополнение к обычным флагам). Значение по умолчанию вы можете выбрать любое.

- Ваш код будет компилироваться так (размер буфера 42 приведён в качестве примера):
  `cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 <files>.c`
  (Примечание: файлы должны находиться в корне репозитория.)
- Поведение `get_next_line()` не определено, если файл, связанный с файловым дескриптором, был изменён после последнего вызова, а `read()` ещё не достиг конца файла.
- Поведение `get_next_line()` также не определено при чтении бинарного файла. Однако при желании вы можете реализовать логичный способ обработки такой ситуации.

> 💡 Будет ли ваша функция работать, если BUFFER_SIZE равен 9999? А если 1? А 10000000? Знаете ли вы, почему?

<!-- -->

> ℹ️ Старайтесь читать как можно меньше при каждом вызове `get_next_line()`. Если вы встретили перевод строки, нужно вернуть текущую строку.
> Не читайте весь файл целиком, чтобы потом обрабатывать его построчно.

**Запрещено**

- В этом проекте нельзя использовать вашу `libft`.
- Функция `lseek()` запрещена.
- Глобальные переменные запрещены.

## Глава VI — Бонусная часть

Этот проект простой и не предполагает сложных бонусов. Однако мы верим в вашу изобретательность. Если вы выполнили обязательную часть, попробуйте выполнить и бонусную.

Требования к бонусной части:

- Реализуйте `get_next_line()`, используя только одну статическую переменную.
- Ваша `get_next_line()` должна уметь работать с несколькими файловыми дескрипторами одновременно.
  Например, если вы читаете из файловых дескрипторов 3, 4 и 5, вы должны иметь возможность при каждом вызове читать из разных дескрипторов, не теряя состояние чтения каждого из них и не возвращая строку из другого дескриптора.
  Это означает, что вы должны иметь возможность вызвать `get_next_line()` для чтения из fd 3, затем из fd 4, затем из fd 5, затем снова из fd 3, снова из fd 4 и так далее, не теряя состояние чтения для каждого файлового дескриптора.

Добавьте суффикс `_bonus.[c\h]` к файлам бонусной части.
Это значит, что помимо файлов обязательной части вы сдаёте в корне репозитория следующие 3 файла:

- `get_next_line_bonus.c`
- `get_next_line_bonus.h`
- `get_next_line_utils_bonus.c`

> ⚠️ Бонусная часть будет оцениваться только в том случае, если обязательная часть выполнена идеально. «Идеально» означает, что обязательная часть выполнена полностью и работает без сбоев. Если вы не выполнили ВСЕ обязательные требования, бонусная часть не будет оцениваться вообще.
